Folder structure
Key concept: Rule:
lib/api/ contains plain async functions — no useQuery, no React.
hooks/ wraps them with TanStack Query.
Components only call hooks, never fetch directly.
This separation means you can swap the API layer without touching any component. 
    app/
    └── news/
        └── page.tsx              ← Route entry point (Server Component)

    components/
    └── news/
        ├── NewsFeed.tsx           ← Client Component, owns the list
        ├── NewsCard.tsx           ← Single article card (pure display)
        ├── NewsFilterBar.tsx      ← Ticker + category filter UI
        └── NewsSkeleton.tsx       ← Loading placeholder

    hooks/
    └── useNews.ts                 ← All TanStack Query logic lives here

    lib/
    └── api/
        └── news.ts                ← Raw fetch functions (no React)

    types/
    └── news.ts                    ← NewsArticle, NewsFilter interfaces
Type definitions
Key concept: nextCursor is the key to infinite scroll. The API returns a cursor pointing to the next page. When it's null, you've reached the end — this is how TanStack Query's useInfiniteQuery knows to disable 'load more'.
API layer
Key concept: Notice: no try/catch here. TanStack Query catches thrown errors and puts them in the error state automatically — handling it in the fetch function would swallow it before Query can see it.
Note: next: { revalidate: 60 } is a Next.js App Router feature. It caches the fetch response at the server level for 60 seconds, reducing load on your news API.
Start with a mock. Before wiring up a real API, return a hardcoded NewsFeedPage from fetchNewsPage. This lets you build and test every layer above it (hook, component, store) without needing a backend running. When you swap the mock for a real fetch, only lib/api/news.ts changes.
useInfiniteQuery hook
Key concept: queryKey: ['news', ticker, category] is the cache address. Change the ticker? The key changes, Query treats it as a brand new query and fetches fresh data — but the old ticker's data stays cached so switching back is instant.
Zustand filter store
Key concept: Zustand stores UI state (what the user has selected). TanStack Query stores server state (the articles). They connect in the component: read filter from Zustand, pass it to useNewsFeed(filter). When Zustand updates, the hook re-runs with the new queryKey.
NewsFeed component
Key concept: data?.pages.flatMap(p => p.articles) is the canonical pattern. useInfiniteQuery keeps all pages in memory as an array of pages — flatMap collapses them into one list. The ?? [] fallback handles the initial undefined state before data loads.
Good for performance! Prefetch on hover
Key concept: prefetchInfiniteQuery uses the same queryKey as useNewsFeed — so when fetchNextPage() is called, the data is already in the cache and renders instantly. This is the 'wow factor' moment on the News Feed page.
Good for performance! Route entry point
Key concept: HydrationBoundary is optional but powerful. It lets the server prefetch the first page and send it embedded in the HTML — the client renders instantly with real data, no loading skeleton on first visit.
